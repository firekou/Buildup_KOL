# 內容產出規則（發文企劃 / AI 生成素材）

適用於所有 KOL 的貼文文案、拍攝腳本、AI 生成圖片與影片產出。與 `style-guideline.md` 的視覺美學規則並行使用——那份講「長什麼樣子」，這份講「文案語氣」與「怎麼拍才可行」。

## 文案語氣

- 日常生活感優先。寫成隨手記錄的真實感，**不要寫成講道理的教學文，也不要用格言/詩句式的結尾金句**。
- 用真人平常真的會發的口語：短句、可以有語助詞（哈、蠻、超、欸）。
- 仍可留一個問句收尾，但要像隨口問一句，不是「留給觀眾深刻反思」那種刻意收束。

## 平台格式

- 小紅書本來就是圖文筆記平台起家，**純圖文（不含影片）是主流格式**，可以直接發純圖文，不用勉強每篇都配影片。

## 影片拍攝規則（全部影片一律適用）

- 一律當作「手機手持、一鏡到底」拍攝：**不切鏡、不加轉場、不加特效**。
- 可以用運鏡（推近、橫移、跟拍、仰俯角）做敘事節奏，但整支影片是同一顆鏡頭完成。
- 單鏡到底的內容，時間跨度必須是「人類實際上真的能一次拍完」的範圍。**不能用一鏡帶過跨越數小時甚至一整天的內容**——例如「一鏡拍一座城市從清晨到深夜」不可行，要改成單一時段、單一場景的一鏡到底。
- **目前使用的 AI 生成工具，影片時長無法超過 15 秒**——所有影片 prompt 的總長度都要控制在 15 秒以內（例如寫「約 10-15 秒」「不超過 15 秒」），不要再寫 15-20 秒或更長的區間。
- **動作類影片不要寫成逐秒時間軸腳本（【0:00-0:03】這種格式）**，這種寫法會讓 AI 生成的動作變得一格一格、卡頓不流暢。改用連續流暢的敘述文字描寫整個動作的先後順序（用「接著」「緊接著」「這一瞬間」等銜接詞），但仍要明確描寫動作是連續一氣呵成、沒有中途停頓，避免出現含糊的「站著不動」空檔（這種空檔容易讓 AI 自行加戲、演出多餘動作甚至犯規動作）。
- **牽涉到真實世界距離感的畫面（例如三分線、球場尺寸、道具間距），光寫數字距離 AI 不一定會準確呈現，要用畫面裡看得到的視覺線索去強化**——例如描寫地面的三分線標線清楚可見、遠處籃框因距離而顯得偏小、人物與目標物之間有明顯可見的空地，讓距離感從畫面構圖本身就成立，而不是只靠 prompt 裡的一個數字。
- **收到參考照片時，先確認客戶的意圖是「直接拿來當圖生影片的起始幀」還是「只是給我看構圖，讓我用文字描述出相近的畫面」，兩種用途寫法不同**：前者才需要在 prompt 裡明講「沿用該圖作為起始幀」；後者純粹是參考、不代表最終會用該圖片本身生成，prompt 只需要用文字重新描述出相近的人物/背景相對位置、距離、留白，不要寫成「沿用已生成參考照片」這種暗示會直接沿用該圖檔的說法，以免與客戶實際操作方式不符。
- **手持一鏡到底的影片，可以搭配畫面外（掌鏡者/朋友）的自然反應音效（尖叫、歡呼、笑聲、驚呼）增加真實感**，尤其是進球、開獎、驚喜等有明確「結果瞬間」的橋段——描述時強調是自然真實的反應音，不是配樂式或誇張的音效。
- **不要加背景音樂**——全程只有人聲（對白/旁白）與場景自然環境音（風聲、腳步聲、環境雜音等），不要在 prompt 裡要求或暗示加入配樂、BGM 這類音樂元素，維持手機隨手拍的真實感，不是有後期配樂的成品廣告感。**實測發現 Seedance 2.0 有時會自行加入背景音樂，即使 prompt 完全沒要求**——每一段對嘴/旁白的 prompt 都要額外明講一句否定指令，例如「全程不可有背景音樂/配樂，只有人聲和環境音」，不能只在規則文件裡寫、每次生成都要重申。
- **全程對嘴講話的鏡頭如果嘴型跟音訊對不上，通常是文案字數/語速沒抓準，導致生成模型自己延展或壓縮音訊長度來配合影片長度**——遇到嘴型對不上時，優先檢查該段文案字數是否符合「(秒數-1)x6.3字/秒」的預算（見下方多段落規則），字數不合就先調整文案重新生成，而不是重複用同一份文案硬試。
- **牽涉兩人以上肢體互動的場景（例如籃球單挑防守、任何有身體接觸可能的對戰情境），AI 很容易生成看起來像犯規/推人/拉扯的動作**——實測籃球投籃案例：從「一對一單挑」開始，即使 prompt 已經精細寫明「兩人保持1公尺距離」「手張開但不觸碰」，甚至改寫成逐秒腳本嚴格規定雙方動作，都還是不穩定。**最後真正解決的做法是拿掉第二個人，改成單人動作**（例如「一對一單挑投籃」改成「單人練習三分球」）。如果內容的重點不是兩人實際攻防互動本身，優先簡化成單人畫面，不要指望靠更精細的空間描述去馴服這個問題。
- **同一種畫面瑕疵如果已經用 2-3 種不同的否定指令/描述方式都沒能穩定解決（例如上述籃球案例的兩人接觸動作、Faye Tan 第一人稱視角持續冒出的手/自拍棒握把），與其繼續加更精細的文字去對抗模型的頑固先驗，改考慮兩個方向**：(1) 直接簡化或拿掉造成問題的元素本身（拿掉第二個人、拿掉容易冒出道具的視角設定）；(2) 評估這個殘留瑕疵是否真的影響內容核心賣點，不影響的話就接受它、不要為了追求零瑕疵無限重新生成——重新生成的邊際成本會遠高於瑕疵本身帶來的損失。
- **動作類影片如果有一個特別難生成正確的瞬間動作（例如起跳出手的人體動作細節），可以用鏡頭甩鏡/急速搖鏡帶到旁邊更好生成的視覺元素（例如籃球飛行軌跡、進網瞬間）去帶過那個瞬間，讓人物暫時離開畫面**——這樣既維持「一鏡到底」的規則，又避開最容易生成失敗的身體動作細節，是很實用的迴避技巧。

## AI 生成素材的限制

所有圖片與影片素材都是 AI 生成，腳本與拍攝說明**不能要求 AI 難以生成或根本生不出來的東西**：

- **不要求清楚可讀的畫面文字 / UI 介面文字**——螢幕、遊戲介面等一律用抽象色塊、光效帶過，不寫出實際文字內容。**例外：單張靜態圖片（不是影片）** 因為不需要跨影格保持一致，風險比影片低很多，可以大膽一點放幾個字的手寫關鍵字直接呼應文案核心觀點（例如筆記本上寫「不是對手」），但仍要控制在十餘字以內、字體大、筆畫簡單，不要整段密集小字——影片仍完全避免任何清楚可讀文字。
- **手機/螢幕入鏡的每一段影片 prompt 都要重複寫一次「螢幕保持純色/漸層模糊，完全沒有任何圖示、按鈕、文字或可辨識介面元素」這句否定指令，不要只在第一段寫、後面幾段省略**——模型容易在沒有再次提醒的段落自行腦補畫面文字或介面圖示，同一支多段影片裡每一段都要各自重申一次，不能假設模型會沿用前一段的限制。
- **單一鏡頭裡如果角色有「轉身看別的方向、再轉回來」的動作（例如回頭看身後，再轉回正面），要注意轉回來之後的背景/朝向是否會跟轉身前的畫面兜不起來**——同一個鏡頭連續生成時，模型對「转回同一個方向後應該看到同樣背景」沒有保證，容易生成兜不上的背景，看起來像換了場景。**優先做法：把「轉身」改成「只有頭部回望，身體/鏡頭朝向全程不變」**，避免整個構圖需要重新想像兩次「面向同一方向」的畫面。
- **第一人稱視角（「她自己的眼睛看著前方」這類描述）容易被模型腦補成「舉著手機/自拍棒在拍」，生出手機（甚至帶滿版亂編 UI 文字，非常明顯穿幫）、行李箱邊緣、自拍棒握把等道具卡在畫面前景，而且常常前後畫面矛盾**。實測發現：即使 prompt 明講「完全不會出現她的手、身體、手機、行李或任何隨身物品」，Seedance 2.0 仍會頑固地在畫面下緣塞入一隻手抓著類似自拍棒握把的物體（試了3次都沒完全排除，客戶已確認不再繼續糾結這點）。**目前的做法：**
  - **手機螢幕帶清楚可讀 UI 文字、行李箱等「有明確物品輪廓」的道具，仍要用明確否定指令排除**（這類的確可以透過否定指令壓下去）。
  - **偶爾在畫面邊緣出現一隻手/類似握把的物體，視為第一人稱手持視角的自然特徵、可以接受，不用再為了排除它重新生成**——與其糾結在這點反覆重來，不如把它當作手持 vlog 感的一部分。
  - 如果拍攝角度描述改成「胸前掛式運動相機/bodycam 視角」而非「手持自拍」，模型比較不會聯想到自拍棒握把，之後可以優先嘗試這種寫法，但不用強求一定要做到零手入鏡。
  - **第一人稱自拍視角時，伸長手臂朝鏡頭方向伸展容易被畫成明顯拉長、扭曲變形、比例不自然**——這跟上面「握把道具」是不同的瑕疵，不是邊緣卡一隻手那種程度，是整條手臂比例跑掉，畫面看起來會很怪，**不算可以接受的殘留瑕疵，要主動避免**。實測案例：Faye Tan 手持風扇邊走邊自拍的片段，伸向鏡頭的手臂被畫得過長、變形。**寫這類「手臂伸向鏡頭」的自拍動作時，要額外加一句明確指令「手臂比例自然，沒有拉長或扭曲變形」**，並優先描寫成手肘微彎、手機/道具維持在較近身體的位置（例如胸口前、臉側），不要寫成手臂完全打直、大幅度伸向鏡頭正前方——伸展幅度越大、越正對鏡頭，越容易誘發這個透視誇大的問題。
- **Seedance 2.0 有時會自行在畫面上疊加燒錄字幕，逐句對應口白內容，即使 prompt 完全沒要求加字幕**——這是另一個常見的自行腦補，要在 prompt 裡額外加一句明確否定指令，例如「畫面上不疊加任何字幕或文字」，才能避免生出來的影片自帶一層預期外的字幕層。
- **畫面中出現任何文字（手寫筆記、標語、招牌等）時，簡體/繁體要對應該 KOL 的國籍/所在地，寫 prompt 前先查該角色 `profile.json` 的 `ethnicity`/`origin`/`current_location`**：新加坡、馬來西亞、中國大陸籍角色一律用簡體字；香港、台灣籍角色用繁體字。目前三位角色：xiaoxiao-tan、loima-cheung（馬來西亞人）與 faye-tan（新加坡人）都適用簡體字。
- **這條簡繁規則同樣適用於貼文文案本身（客戶已確認）**：貼文文案是這三位角色實際會公開發表的文字，不只是畫面裡的視覺文字，一樣要依角色國籍決定簡繁——xiaoxiao-tan、faye-tan、loima-cheung 的所有貼文文案一律用簡體字寫。內部工作文件（prompt 說明、拍攝細節、規則文件本身）維持繁體字，不受此規則影響。
- **不要求精確重現特定真實版權內容**——例如指名某部電影的某個經典鏡頭、某款真實遊戲的實際介面。改用不指名、泛用/原創風格的畫面（「一個電影感的暫停畫面」而非「XX 電影裡 XX 角色的那個鏡頭」）。
- **不要求生成撲克牌、骰子等有精細花色/數字/點數圖案的道具特寫**——這類小型精細圖案 AI 經常生成錯誤或扭曲，一樣用抽象形狀（方框、箭頭、簡單圖形）取代，不畫實際牌面。
- 場景描述盡量靠「環境、光線、動作、道具」構成畫面，不要依賴精確文字或可辨識的特定版權素材。
- **檢查鏡頭視角的邏輯一致性，不要寫出自相矛盾的描述**——最常見的錯誤是「第一人稱視角」卻同時要求該視角的拍攝裝置本身入鏡。例如自拍是手機前鏡頭自己拍自己，手機本身邏輯上不可能出現在自己的畫面裡，只有伸長的手臂/手可以入鏡到畫面邊緣；同理，任何宣稱是「某個角色的主觀視角」的鏡頭，都不該同時要求該角色的臉或該視角所用的裝置完整入鏡。寫每一則 prompt 前，先想一下鏡頭實際擺在哪裡、看得到什麼、看不到什麼。
- **這條邏輯不只適用「自拍」，任何「這張圖／這段影片本身就是角色用手機拍出來的內容」的設定都適用**——例如「他舉著手機拍電視」這種構圖，如果目的是要生成「他實際拍下來的那張照片」本身，手機（不管前鏡頭自拍還是後鏡頭拍別的東西）本身都不該出現在畫面裡，因為拍攝裝置不會出現在自己拍出來的成品畫面中。實測案例：xiaoxiao-tan 一張「第一人稱視角看電視」的圖文照片，一開始寫成「手舉著手機、手機背面入鏡、電視在後方」，被客戶指出手機不該出現在照片裡——正確做法是把手/手機整個拿掉，畫面直接就是電視螢幕本身的特寫，當作是手機實際拍出來的那張照片。如果真的需要「有人在拍」這個動作被看見，那就不是第一人稱視角，要明確改寫成第三人稱／旁觀者視角（另一台鏡頭從外部拍到他舉著手機拍電視的畫面）。

## 拍攝細節：鏡頭與服裝

- **鏡頭位置、距離、人物在畫面中的相對位置一定要寫清楚**，不能只寫「拍他的臉」「拍全身」這種模糊描述。每一則 prompt 都要包含：
  - 鏡頭角度/高度（仰角、俯角、與人物視線同高、與坐姿肩膀齊平等）
  - 鏡頭與人物/主體的距離（用公尺數具體寫出來）
  - 人物在畫面中的位置與佔比（例如「畫面左側三分之一」「置中、佔畫面高度 10-15%」）
  - 影片還要寫清楚運鏡路徑（推近/橫移/跟拍時，距離與角度如何隨時間變化）
- **所有素材統一套用 iPhone 15 主鏡頭拍攝質感**（自然電腦運算 HDR、真實色彩與皮膚/材質細節、無明顯後製痕跡、不過度銳化），除非另有指示。
- **第一人稱視角（她自己的眼睛/手機視角，看不到她本人的臉或身體）的 prompt 不需要描述服裝造型**——反正畫面裡本來就看不到她穿什麼，寫了也沒用，甚至可能誤導模型把她的身體畫進畫面。只有第三人稱（看得到她本人入鏡）的 prompt 才需要寫服裝。
- **服裝要依情境穿著，不強制整套角色設定裡的招牌穿搭套用到所有場景**。例如平常走知性極簡風的角色，去打球時要換成球衣/運動服，不能還穿西裝外套打球；出門逛街機店要換外出休閒服，不是在家的居家服。每一則有人物入鏡的 prompt 都要明確寫出當下情境該穿什麼。
- **同一件單品不要重複套用在下一支新影片上**——每次要生成新的一支影片（新的定裝照/參考圖流程）時，即使場景/情境類似，也要換一套沒用過的服裝款式，避免每支影片看起來都在穿同一件衣服。已經在跑的生成不用重做，這條只套用在下一次新開始的生成。
- **參考圖標籤統一用 `@Image N` 格式（不要用中文的 `@圖N`）**，依實際餵給模型的順序編號，不限於人物照——例如 `@Image 1 @Image 2 @Image 3 是 Faye Tan，@Image 4 是背景參考，@Image 5 是服裝參考`，把每張參考圖的用途都寫清楚。
- **`@Image` 人物參考標籤要跟內文用名字的方式綁定，不能各寫各的**：如果 prompt 內文會直接寫出角色的名字（例如「Tan XiaoXiao 站在...」），人物那幾張 `@Image` 後面就要接著寫「是〔名字〕」，明確告訴模型這些參考圖對應哪個名字。如果內文不打算寫名字，標籤就維持「人物參考」這種泛用寫法，內文全程只用「人物 / 他 / 她」代稱，不要中途夾雜名字。兩種寫法擇一，不要混用。

## 影片格式：B-roll 主體+結尾短句 vs. 全程對鏡頭講話

- **兩種格式都可以用，依內容/題材判斷哪種更適合，不是固定只能用其中一種**：
  - **B-roll 主體+結尾短句**：畫面主體是動態情境 B-roll（寫筆記、逛市場、滑手機等），鉤子文案當作 OS 字卡/旁白呈現，只在結尾留 2-3 秒的短句對鏡頭作結。適合有明確動作/道具可以拍、不需要角色逐句解說的題材。
  - **全程對鏡頭講話**：角色從頭到尾直視鏡頭說完整段文案，可以搭配手勢/道具互動（例如指向桌上的道具、比劃動作）。適合需要角色完整說明一個邏輯、清單或反轉論點的題材——這類內容硬要拆成「B-roll+3秒金句」反而會讓資訊講不清楚。
  - 兩種格式都可以分段生成（見下方多段落技術規則），不限於單段 15 秒以內。
- 影片時長盡量抓滿 15 秒上限（不要為了省事縮到 5-8 秒）；用 B-roll 格式時，前 11-12 秒是**旁白貫穿、畫面不對嘴**（鉤子文案當成連續的OS旁白唸出來，配B-roll動態畫面），最後 2-3 秒才切到角色對鏡頭、對嘴講結尾短句。
  - **切勿把「前11-12秒無對嘴」誤讀成「前11-12秒完全靜音」**——2026-08-05 曾實際做錯過一次：把B-roll段落整段留白不放任何旁白，只在結尾塞一句對嘴短句，客戶當場指出「為什麼運鏡那麼久卻只講一句話」。正確做法是旁白從第1秒就開始唸鉤子文案，唸到差不多告一段落時無縫接上結尾那句對鏡頭對嘴的短句，全程都有聲音，只是「對嘴」跟「純旁白」的畫面配置不同。
  - 如果題材本身文案不長、或客戶更看重直接感，可以直接放棄B-roll、整段改用全程對鏡頭講話格式（同一支影片的所有段落要統一格式，不要有的段落B-roll有的段落對鏡頭）。用全程對鏡頭講話時，**鏡頭的水平位置也要明確寫出來**（例如「鏡頭正對他的正前方」），不要只寫高度/距離/景別卻漏了角色與鏡頭的左右/正對關係。
- 需要生成語音時，用生成工具的預設自動配音即可，不需要特別指定/試聽某個聲音模型——除非客戶另外要求。
- **全程對嘴講話的鏡頭（Seedance 2.0 實測校準）：語速用「語速明快、節奏緊湊、中間不停頓、一氣呵成」這類描述去寫 prompt，抓約 6.3 字/秒**（比一般抓 3.5 字/秒的節奏快上不少），客戶已確認這個語速可行。這個校準只適用於「全程說話」的鏡頭，B-roll 主體+結尾短句那種格式不受影響。
- **每一段結尾要留約 1 秒的無台詞緩衝空白，不要讓台詞剛好講完就是影片結尾**——同樣的秒數設定，文案字數要比單純「秒數 x 6.3字/秒」再少一點（實測發現字數抓滿整個時長會讓結尾顯得倉促、卡在講到一半的感覺）。換算下來一顆 15 秒的鏡頭，文案抓約 80-88 字（用 14 秒的講話時間去算，而不是滿 15 秒）；14 秒的鏡頭抓約 75-82 字，以此類推。
- **一段影片如果因為秒數關係，最後一句台詞被迫講得倉促、卡在句尾，優先做法是把那句話整句移到下一段的開頭重講一次，而不是硬把它塞在快結束的段落裡**，讓每句話都有足夠的時間自然講完。
- **超過 15 秒的長影片，分段生成時不要用「首尾幀接續」（Seedance 2.0 實測發現：用前一段的結尾幀當下一段的 `start_image`，色調會隨著接續次數越來越暗沉、失真，這是接續生成的通病，不是換張圖就能解）。**
- **正確做法：每一段都獨立生成，不帶 `start_image`，靠固定的參考圖組合讓畫面盡量像同一顆鏡頭，段落間接受有看得出來的跳接（這其實更貼近真人 vlog 分段拍的真實感，不算缺點）。固定用這組參考圖（`image_references`）**：
  1. 3 張人物參考照（跟平常一樣，建立臉部身份）
  2. **服裝參考圖：先用 i2i 從乾淨的定裝照去除人臉/頭部/背景，只留衣服本身**——如果服裝參考圖裡還留著臉或背景環境，會干擾模型、讓後面段落的色調跑掉。**呈現方式要用「人形模特架/假人台（headless mannequin）+ 純色攝影棚背景」的服裝型錄照風格，不要是懸空、去背後變形的衣服剪影**——客戶已確認這個呈現方式，之後所有角色都比照辦理
  3. **背景參考圖：同樣用 i2i 從定裝照移除人物，只留空的場景環境**
  4. 聲音參考（`audio_references`，同一份人聲音檔，`generate_audio:true`）
  - 每段文字內容不同，但服裝/背景/鏡頭角度的文字描述維持一致。
- **流程順序（客戶已確認的做法）：先用 3 張人物參考照生成一張「定裝照」（人物在目標場景中的單張靜態圖），再從這張定裝照分別做出服裝參考圖與背景參考圖，最後才開始生成第 1 段影片**——不要像最早期那樣先生成第 1 段影片、事後才從影片截圖去做參考圖，先把兩張參考圖準備好，讓包含第 1 段在內的所有段落都能套用同一組參考圖。
- **每個 prompt list 檔案的最後，都要另外加一個「全片文案彙整」段落，把每一段實際說出的文案原文，依段落順序單獨列出來（不要混在 Prompt 描述裡）**——這是給客戶核對後製字幕用的，格式簡單列「【第1段】文案內容」逐段列到最後一段即可。

## 內容發想：爆款搜尋與排重流程

- **每次發想新題材前，先讀 GitHub `main` 最新版的 `kols/content-history.md` 與本規則檔，再開始找題。** 排重永遠先於爆款搜尋，不能先看到一個熱門題目就直接寫腳本。
- **先排除 content-history 裡已完成、已定案、進行中，以及曾被客戶拒絕的題材。** 排重不能只看標題，要比對核心概念、知識點、心理機制、主要鉤子、故事結構與呈現角度；只換案例、數字、地點或標題，但核心機制相同，仍算重複。
- 完成排重後，才開始做 **benchmark／網路爆款搜尋**。優先找：
  1. 各角色已指定的標竿／對標帳號與其高互動內容。
  2. TikTok／抖音／Reels／YouTube Shorts 等平台近期高觀看、高互動或被大量模仿的短影音。
  3. 當週熱門話題、熱門搜尋與角色所在地相關時事。
  4. 沒有合適近期素材時，再找已被長期驗證、仍有大眾吸引力的 evergreen 爆款題材。
- **不直接照抄爆款作品。** 找到參考內容後，要先拆出可以移植的參數，例如：前 3-6 秒鉤子、反差／懸念點、最容易被記住的資訊、段落節奏、反轉位置、低門檻互動方式，再把這些結構改寫成符合該 KOL 人設與內容支柱的新內容。
- **「很紅」不能凌駕於 history 排重。** 如果爆款題材與已做過或被拒絕題材的核心機制重疊，直接淘汰，繼續搜尋下一個，不因為原片觀看高就重新包裝再提一次。
- **搜尋到的爆款只代表「有人願意看」，不代表事實一定正確。** 凡涉及數字、研究、政策、新聞、平台機制、歷史事件或真實案例，寫腳本前都要另外查證可靠來源與日期；無法驗證的細節不要寫死。
- **固定工作順序：`content-history 排重 → benchmark／爆款搜尋 → 拆 hook／記憶點／結構 → 角色適配 → 事實查證 → 文案／腳本`。** 不再以「先想這個 KOL 今天可以講什麼」作為主要起點。
- 每次有採用外部爆款／標竿內容作為靈感時，**在該次企劃或 prompt list 的過程備註中留下簡短來源紀錄**：至少記錄平台／帳號或來源名稱、參考內容主題，以及實際借用的是哪個結構（例如鉤子、反差、段落、互動），方便之後回頭檢查來源與避免重複取材。
- 更完整的爆款拆解方法、母公式與四維判準，與 `docs/06-viral-content-framework-and-four-axis-judgment.md` 並行使用；本節負責規定「每次選題必須先做什麼」。

## 內容發想：蹭時事

- **構思貼文題材時，先看有沒有剛好能結合的時事**——如果有一則時事跟角色設定的發文主題（例如 Tan XiaoXiao 的機率/博弈規則、Faye Tan 的城市觀察、Zhang Qinfeng 的數位體驗設計）能自然對上，優先用這個時事當題材，比純憑空發想更好。
- 時事**以角色所在地當地新聞優先**（新加坡、馬來西亞），沒有合適的當地新聞時，全球性的時事也可以接受。
- **絕對不要為了蹭而硬套**：如果當下沒有真的跟主題契合的時事，就照原本的方式發想題材，不要為了蹭話題勉強牽拖一則關係很遠、很牽強的新聞進來，牽強感會比沒有時事更糟。

## 各角色要避免的內容類型

找參考影片/發想題材時，先排除以下角度——這些是 AI 生成成本太高、風險太高、或效果打折扣的類型，不用浪費時間往這些方向搜尋或改編。

### 通用（適用所有角色）

- **強調「自身親身經歷」的敘事類型**——例如「這是我真實遇到的事」「我上次親身經歷」這種強調第一手真實經歷的角度，由 AI 虛擬角色講出來說服力不足，觀眾容易感覺是編的，不夠真實可信。改用「查了資料才知道」「觀察到的現象」「聽說/研究顯示」這類角度，不強調是角色本人的親身經歷。

### Tan XiaoXiao

- **涉及兩人以上肢體接觸互動的畫面**（例如籃球單挑防守）——AI 容易生成看起來像犯規/推人的動作，實測試了很多種寫法都沒穩定解決，最後只能放棄改成單人動作。
- **撲克牌、骰子等精細花色特寫**——AI 常畫錯/扭曲花色與點數，一律用抽象形狀代替。
- **勸人戒賭/道德勸說類角度**——不要走「賭博不好、勸你戒賭」這種說教方向，人設定位是中立客觀分析機率/心理機制背後的「為什麼」，不做道德判斷、不做戒賭宣導。

### Faye Tan

- **食物試吃類**——咀嚼/吃東西的動作 AI 生成不自然。
- **介紹特定真實店家/場所**——AI 生不出真實存在的招牌、店面。
- **建築取景類**——說服力不足，且跟她慣用的手持自拍格式不搭。
- **快速切換多個場景的旅遊剪輯類**（例如一支影片跑好幾個不同地點/景點）——這種格式需要生成很多不同場景的素材，AI 生成成本太高，不划算。

### Zhang Qinfeng

- **具體遊戲畫面/介面特寫**——AI 無法準確重現任何真實遊戲的 UI、關卡畫面。
- **具體品牌的主機/週邊開箱**——AI 生不出真實存在的品牌商品外觀。
- **點名真實電競選手/賽事**——涉及真人肖像與真實賽事畫面，風險高。
