# AI Token King（gpt-5.5）對 docs/10 簡化提案的 Review

## 砍錯了

1. **第一刀：八軸砍到四軸的證據不足，尤其不該直接刪 `daily`。**  
   現在五位 KOL 都在 draft，拿「現有數字直接驗算」不能證明排序不受影響，因為沒有真實選題與發布結果。砍掉 `daily` 的後果是：可複製、日常、陪伴型題材會被誤判成只是格式問題，最後可能派給高權威或高視覺但不貼近生活的 KOL。

2. **第二刀：地區從計分改成標示有問題，會破壞現行 §6(b)「話題 → KOL」排序。**  
   同一個話題拿來比五位 KOL 時，地區與語言不是常數；它直接影響誰適合接這題。後果是：人設與支柱分高但語言／地區不合的 KOL 可能排到前面，只靠 UI 標示會把決策責任丟回人工。

3. **第二刀：紅線嚴重度三級砍成一級，會在過度封殺與風險消失之間二選一。**  
   現行 §3.6 的 `veto`、`high`、`medium` 不是同一件事；`veto` 是不能做，`high/medium` 是要降權或提醒。後果是：博弈、醫療、金融這類灰區題材要嘛全部被擋掉，要嘛進入推薦清單時失去風險層級，合規判斷反而更粗。

4. **第三刀：刪 `material_attributes` 與拿掉 `topic_hooks[].axis_demand` 都砍過頭。**  
   現行 §2 的可執行性檢查不只是讀色盤或數圖檔，還包含模型、Reference Element、一致性策略、可用格式；刪掉後會產出 Match 很高但生成不可行的素材骨架。拿掉 `axis_demand` 也會把具體 hook 壓平成 domain 平均，後果是同一領域裡「理性解釋型」與「情緒故事型」題目被同一套需求誤配。

5. **第五刀：砍假預測是對的，但把後評從現行 §4.2 的 11 個欄位砍到 3 個數字會造成資料永久不足。**  
   可以刪 `predViews/predClicks` 這類假公式，但不該刪 `profile_visits`、`completion_rate`、`conversions` 等實際欄位；這些不是預測，是之後歸因需要的原始事實。後果是：等真的累積 10、50 筆後，仍然無法分辨是選題差、完播差、CTA 差、profile 承接差，校準也無法補回已經沒存的資料。

## 砍不夠

1. **現行設計 §1.1「Tag 規則微調」應砍掉。** 第三刀拿掉 `topic_hooks[].axis_demand`，但如果還保留 `classify.js` 依關鍵字對軸加減分，實際上只是把手填覆寫換成隱藏覆寫；目前 0 筆實績，沒資格維護這種細規則。

2. **現行設計 §3.3「手動綁定支柱給下限 70」應砍掉。** 人工綁定可以保留，但不應自動保底 70，否則編輯一綁定就把 scoring 繞過了；改成只標記 `bound: true`，分數照算。

3. **現行設計 §3.3「無支柱對應的封頂曲線」應合併成單一 Gate。** `min(raw, 54 + 0.1·raw)` 這種曲線沒有資料依據，也很難解釋；無支柱就標示「不推薦／需人工綁定支柱」，不要再做一條假精密封頂公式。

4. **現行設計 §4.1「四維預估門檻」應從 Dashboard 評分移出。** 娛樂性、音樂性、真實性、動作流暢性是在判斷成片品質，不是選題配置；最多放在「素材企劃檢查清單」，不要和 Match 分數一起形成第二套開工門檻。

5. **現行設計 §6「交叉查詢的聯集與三個以上 Tag」應砍掉。** 文件自己已經說最有價值的是兩個 Tag 的交集，三個以上通常無資料；UI/API 只留「單一 Tag」與「兩 Tag 交集」，聯集先不要做。

## 邏輯漏洞

1. **第二刀的 Gate 2 其實不是 gate，會在現行設計 §6(b)「話題 → KOL」失效。**  
   提案說「話題地區不在 KOL 覆蓋範圍 → 標示，不參與排序」，但 §6(b) 是同一個話題拿去排全部 KOL，地區契合正是排序差異來源；拿掉後，非目標地區 KOL 可能排在前面，只是被標示一下。

2. **第二刀把紅線嚴重度砍成一級，會讓現行設計 §3.6 的非 veto 風險消失。**  
   不是所有風險都應該一票否決，但 `high` / `medium` 被刪後只剩「擋」或「不擋」：關鍵字設太寬會過度封殺，設太窄則原本應降權的高風險題會照常進推薦。

3. **第三刀刪 `material_attributes`，但第七刀和現行設計 §6(c) 還要輸出「建議格式／可用場景／視覺語言」，會產生資料來源斷裂。**  
   `profile.json content.aesthetic` 和數目錄只能補一部分，補不了現行設計 §2 的生成模型、一致性策略、Reference Element、可用格式；結果是素材骨架還在，但可執行性判斷變弱或變成硬猜。

4. **第一刀刪 `daily`，但第七刀仍保留「建議格式」，兩者邏輯衝突。**  
   提案說 `daily` 是格式問題所以不該進選題模型；但如果 dashboard 仍要建議 vlog／日常感格式，就需要某個欄位描述 KOL 是否撐得起日常拍法，否則「格式建議」會變成沒有特徵支撐的孤兒功能。

5. **第五刀改成人填目標、第六刀刪校準，會切斷現行設計 §4.1／§5 的模型學習閉環。**  
   人填目標適合做企劃承諾，但它不是模型預測，事後落差只能評估「人當初估得準不準」，無法校準 Match 權重或 KOL baseline；等 10 筆後再寫，可能會發現前面沒有存足可回推的預測快照與假設版本。
