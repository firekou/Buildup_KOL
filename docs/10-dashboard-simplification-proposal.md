## 一句話

現在這套東西**算得比它知道的多**。八個軸、五個加權維度、五層漏斗預測，
背後真正有事實支撐的只有「這個人擅長什麼」和「這題現在多熱」兩件事。
提案是把所有**假裝精確**的部分砍掉，留下會改變決定的部分。

---

## 砍東西的三條判準

每一項功能問三個問題，**任何一題答不出來就砍**：

1. **這個數字會改變決定嗎？** 如果 A 案和 B 案排序不受它影響，它就只是裝飾。
2. **這個數字有事實支撐嗎？** 還是從一個假設值乘一個編出來的係數得到的？
3. **誰要維護它？** 每新增一位 KOL 要多填幾個欄位？填錯了會不會沒人發現？

**外部 review 補上的第四條：**

4. **砍掉之後還救得回來嗎？** 砍公式隨時可以重寫；砍掉「不再儲存某個實際欄位」，
   等有資料時就永久補不回來了。**顯示可以少，儲存不能少。**

### 被 review 推翻的判斷（記錄下來，避免再犯）

v0.1 主張「地區在同一份地區清單裡對排序零貢獻，可以從計分改成標示」。
**這個判斷只在方向 (a)「KOL → 話題」成立**——那時所有話題地區確實相同。

但在方向 (b)「話題 → KOL」，是**一個話題去比五位 KOL**，
而五位 KOL 的 `regions` 與 `language` 完全不同（rafael 主力 CN、faye 主力 SG、loima 主力 MY）。
地區在那個方向正是排序差異的來源之一。砍掉它，語言／地區不合的人會排到前面，
只剩 UI 上一個標示，等於把判斷丟回人工。

**v0.2 保留地區計分。** 這一刀我砍錯了。

## 提案內容（八刀）

### 第一刀：屬性軸 8 → 4（`daily` 降級而非刪除）

| 現行 | 合併後 | 理由 |
|------|--------|------|
| `analysis` + `contrarian` | **理性拆解** | 「拆結構」和「打破直覺」在本 repo 的內容裡幾乎同時出現同時消失 |
| `narrative` + `emotion` | **敘事情緒** | 分開打分沒有讓任何一次排序改變過 |
| `visual` + `aspiration` | **視覺張力** | 嚮往感在本 repo 幾乎完全由畫面帶動 |
| `authority` | **身分可信** | 保留，這是唯一無法靠製作補的軸 |
| `daily` | **移出 Match，改放 `format_fit`** | 它影響的是**怎麼拍**，不是**選什麼題** |

`daily` 不進 Match 分數，但保留為一個獨立欄位，供方向 (c) 的素材企劃判斷
「這題適不適合做成日常／隨手感的切角」。**不刪資料，只移出評分。**

合併後五位 KOL 的區辨度沒有下降：

| KOL | 理性拆解 | 敘事情緒 | 視覺張力 | 身分可信 | （format_fit） |
|-----|---------|---------|---------|---------|---------------|
| xiaoxiao-tan | 93 | 53 | 38 | 80 | 55 |
| faye-tan | 55 | 74 | 90 | 60 | 70 |
| loima-cheung | 85 | 60 | 73 | 65 | 60 |
| rachel-ong | 74 | 89 | 94 | 95 | 50 |
| rafael-costa | 65 | 84 | 82 | 92 | 80 |

> **注意這張表的效力有限。** 它證明的是「合併不會讓現有五個人變得分不開」，
> 不是「合併不會影響真實選題結果」——後者在 0 筆實績下無法證明。
> 這是接受這一刀的已知風險。

### 第二刀：Match 五維 → 四維 ＋ 一個 Gate

現在的公式把「分數」和「門檻」混在一起：紅線只佔 10% 權重，
卻又要靠一個 veto 特例把它拉回 0 分——**同一件事寫了兩遍**。

```
現在：0.30·人設 + 0.25·支柱 + 0.20·熱度 + 0.15·地區 + 0.10·(100−風險)  ＋ veto 特例

提案：分數 = 0.35·人設 + 0.30·支柱 + 0.20·熱度 + 0.15·地區
      Gate（紅線）：veto 命中 → 不進推薦清單，只出現在「已排除」並附原因
                    warn 命中 → 照常排序，但列出警告，不扣分
```

**紅線三級 → 兩級。** 現行的 `high` 扣 40 分、`medium` 扣 20 分，
沒有人能說清楚這兩個數字的差別在哪。留兩種狀態：**擋下來**，或**標示出來**。
扣分的算術整個拿掉——風險要嘛足以否決，要嘛只需要讓人看見。

### 第三刀：`topic_affinity.json` 12 段 → 7 段

| 現行區段 | 處置 |
|---------|------|
| `kol_id` | 保留 |
| `version` / `generated_at` / `source` | **刪**——git 已經記錄了這些 |
| `persona_axes` + `axis_evidence` | **合併**成 `axes: { analysis: { score, why } }`，4 軸 + `format_fit` |
| `material_attributes` | **保留但縮減**（見下） |
| `pillar_keywords` | **保留**——pillarFit 準確度的命脈，不能砍 |
| `topic_hooks` | 保留，**拿掉 `affinity` 分數**，`axis_demand` 改為選填 |
| `redlines` | 保留，兩種嚴重度 |
| `reach` | 縮成 `regions` + `language` |
| `baseline_funnel` | **刪**（見第五刀） |

**`material_attributes` 為什麼從「刪除」改成「縮減」：**
v0.1 說可以改讀 `profile.json` 的 `content.aesthetic`。
review 指出那裡只有色盤與剪輯風格，**補不了**生成模型、一致性策略、可用格式——
而方向 (c) 的可執行性檢查正是靠這些。改為只留三個欄位：
`generation_model`、`consistency`、`usable_formats`；視覺語言與色盤改讀 `profile.json`。

**`topic_hooks[].affinity` 為什麼要拿掉：** 它被當成 heat 塞進 Match 公式，
等於**人先給一個分數，再讓引擎算一個分數**。留一個就好，留引擎算的。

**`axis_demand` 從「拿掉」改成「選填」：** review 指出同一個 domain 裡
「理性解釋型」與「情緒故事型」的題目需求並不同，全壓成 domain 平均會誤配。
保留覆寫能力，但**預設不填**，只在確實需要時才用。

新增一位 KOL 要填的數字：**約 60 個 → 約 20 個**。

### 第四刀：熱度三訊號 → 兩訊號

```
現在：0.45·log(量體) + 0.35·成長率 + 0.20·互動率
提案：0.60·log(量體) + 0.40·成長率
```

互動率的問題不是它沒用，是**多數 Apify hashtag actor 根本不回傳這個欄位**。
現在唯一穩定有這個數字的是手寫的範例資料——等於在拿假資料算分。
真的接上 Apify 後，這一項會退化成常數 50，對排序毫無貢獻。

---

### 第五刀（最重要）：「預測漏斗」換成「設定目標」，但**實績照樣全存**

現況：從一個 `assumed: true` 的基準值，乘上 `lift = 0.7 + 0.6·(Match/100)`，
再乘上 `heatMultiplier = 0.85 + 0.3·(熱度/100)`，往下推五層，得到五個小數點以下的數字。

**那兩個乘數是編的。** 沒有任何資料支持 Match 90 分會比 50 分多帶 30% 觸及。
五個看起來精確的數字全建在兩個沒有來源的係數上——這比不預測還糟，
因為它會讓人以為系統知道一些它其實不知道的事。

| | 現行 | 提案 |
|---|------|------|
| 預評 | 5 層漏斗預測 + 2 個乘數 | Match 分數 + 等級 + **企劃者自己填 2 個目標**（目標觀看、目標外連點擊）+ 一句決策 |
| 後評（**儲存**） | 11 個欄位 | **11 個欄位照存**——只要平台給得出來就存 |
| 後評（**顯示**） | 11 個欄位全部呈現 | **3 個數字**（觀看、互動、外連點擊）+ 四維實測 |
| 對照 | 5 列 + 3 種偏差帶 + 5 種歸因 | **3 列** + 一句歸因 |

**「顯示 3 個、儲存 11 個」是 review 逼出來的修正。** v0.1 打算連儲存一起砍到 3 個，
那會讓未來累積到 50 筆時，仍然分不出是完播差、CTA 差、還是主頁承接差——
而那些欄位不是預測，是**當下就能拿到的事實**。存起來幾乎不花成本，砍掉就永遠回不來。

歸因規則同時簡化成兩句話：

- 觸及達標、點擊不足 → **素材問題**（CTA / 結尾）
- 觸及不足 → **選題或發布時機問題**

### 第六刀：刪掉校準迴圈

`calibration()`、Pearson 相關係數、每位 KOL 的建議基準值——
**這套機制要 10 筆完成後評估才會啟動，目前有 0 筆。**
它現在唯一的作用是在畫面上顯示「樣本 2 / 10」。

隨第五刀一起刪除。**但因為第五刀改成「實績全存」，這一刀變成可逆的**：
等真的累積到 10 筆、且有人真的想調參數時再寫，那時候資料是齊的。

### 第八刀（review 追加）：四處 v0.1 漏掉的「假精確」

同一個判準要一致地套在自己身上——以下四項犯的是與漏斗預測相同的毛病：

1. **綁定支柱的保底 70 分**（`docs/09` §3.3）——編輯一綁定就繞過了 scoring。
   改為只標記 `bound: true`，分數照算。
2. **無支柱的封頂曲線 `min(raw, 54 + 0.1·raw)`**（§3.3）——這條曲線沒有任何依據。
   改成明確狀態：**沒有支柱對應 → 標記「需人工綁定支柱」，不給分級**。
3. **Tag 規則微調的軸加減分**（§1.1）——`+15` / `+18` 這些數字同樣是編的。
   0 筆實績下沒資格維護這種細規則，先拿掉，只留 domain 預設。
4. **交叉查詢的聯集模式與三 Tag 以上**（§6）——文件自己就寫了「三個以上通常無資料」。
   只留**單一 Tag** 與**兩 Tag 交集**。

**四維判準改為檢查清單。** 它判的是成片品質（`docs/06` Part D 的既有標準），
不該和 Match 分數一起形成第二道開工門檻。移到方向 (c) 的素材企劃裡當 checklist，
發片前照跑，但不參與「要不要開工」的決策。

## 還沒解決的一個爭議

Review 主張第一刀「用現有五個人的數字驗算合併安全」在 0 筆實績下**不成立**。
這個批評是對的，但它同時也削弱了「維持八軸」的理由——
**0 筆實績下八軸同樣沒有被驗證過**，而八軸的維護成本是四軸的兩倍。

我的立場：先合併成四軸，把省下的維護成本拿去累積實績；
等有 20–30 筆資料，再回頭看是否需要把某一軸拆開。
**如果你不同意這個取捨，請在拍板時說，我就維持八軸只做其餘七刀。**
