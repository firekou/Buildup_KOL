## 一句話

現在這套東西**算得比它知道的多**。八個軸、五個加權維度、五層漏斗預測，
背後真正有事實支撐的只有「這個人擅長什麼」和「這題現在多熱」兩件事。
提案是把所有**假裝精確**的部分砍掉，留下會影響決策的部分。

---

## 砍東西的三條判準

每一項功能問三個問題，**任何一題答不出來就砍**：

1. **這個數字會改變決定嗎？** 如果 A 案和 B 案排序不受它影響，它就只是裝飾。
2. **這個數字有事實支撐嗎？** 還是從一個假設值乘一個編出來的係數得到的？
3. **誰要維護它？** 每新增一位 KOL 要多填幾個欄位？填錯了會不會沒人發現？

## 提案內容（七刀）

### 第一刀：屬性軸 8 → 4

現在八軸裡有三組其實在量同一件事：

| 現行 | 合併後 | 理由 |
|------|--------|------|
| `analysis` 理性拆解 + `contrarian` 反直覺衝突 | **理性拆解** | 「拆結構」和「打破直覺」在這個 repo 的內容裡幾乎同時出現同時消失 |
| `narrative` 敘事張力 + `emotion` 情緒共鳴 | **敘事情緒** | 分開打分沒有讓任何一次排序改變過 |
| `visual` 視覺表現 + `aspiration` 嚮往感 | **視覺張力** | 嚮往感在本 repo 幾乎完全由畫面帶動 |
| `authority` 專業權威 | **身分可信** | 保留，這是唯一無法靠製作補的軸 |
| `daily` 生活貼近 | **刪除** | 它是**格式**問題（要不要拍成 vlog），不是**選題**問題。放在選題模型裡從來沒起過作用 |

合併後五位 KOL 的區辨度沒有下降（用現有數字直接驗算）：

| KOL | 理性拆解 | 敘事情緒 | 視覺張力 | 身分可信 |
|-----|---------|---------|---------|---------|
| xiaoxiao-tan | 93 | 53 | 38 | 80 |
| faye-tan | 55 | 74 | 90 | 60 |
| loima-cheung | 85 | 60 | 73 | 65 |
| rachel-ong | 74 | 89 | 94 | 95 |
| rafael-costa | 65 | 84 | 82 | 92 |

每一欄都還是分得開——這就是合併安全的依據。

### 第二刀：Match 五維 → 三維 ＋ 兩個 Gate

現在的公式把「分數」和「門檻」混在一起算，導致紅線只佔 10% 權重，
卻又要靠一個 veto 特例把它拉回 0 分——**同一件事寫了兩遍**。

```
現在：0.30·人設 + 0.25·支柱 + 0.20·熱度 + 0.15·地區 + 0.10·(100−風險)  ＋ veto 特例

提案：分數 = 0.40·人設 + 0.35·支柱 + 0.25·熱度
      Gate 1（紅線）：命中 → 不出現在推薦清單，只出現在「已排除」並附原因
      Gate 2（地區）：話題地區不在該 KOL 覆蓋範圍 → 標示，不參與排序
```

**地區為什麼可以從計分改成標示：** 話題本來就是「查某個地區」查出來的。
在同一份地區清單裡，所有話題的地區條件相同，這 15% 對**排序完全沒有貢獻**——
它只在跨地區比較時才有意義，而實務上不會那樣用。

**紅線嚴重度三級 → 一級。** 現在的 `high` / `medium` 只是扣分，
但「扣 40 分」和「扣 20 分」的差別從來沒有人能說清楚。留 `veto` 一種：**是紅線，或不是**。

### 第三刀：`topic_affinity.json` 12 段 → 6 段

| 現行區段 | 處置 |
|---------|------|
| `kol_id` | 保留 |
| `version` / `generated_at` / `source` | **刪**——git 已經記錄了這些 |
| `persona_axes` + `axis_evidence` | **合併**成 `axes: { analysis: { score, why } }`，4 軸 |
| `material_attributes` | **刪**——視覺語言、色盤直接讀 `profile.json` 的 `content.aesthetic`，圖檔數直接數目錄 |
| `pillar_keywords` | **保留**——這是 pillarFit 準確度的命脈，不能砍 |
| `topic_hooks` | 保留，但**拿掉 `axis_demand` 覆寫與 `affinity` 分數**（見下） |
| `redlines` | 保留，扁平化成字串陣列 + 關鍵字，只有一個嚴重度 |
| `reach` | 縮成 `regions` + `language` |
| `baseline_funnel` | **刪**（見第五刀） |

**`topic_hooks[].axis_demand` 為什麼要拿掉：** 它讓同一個領域的話題有兩套軸需求
（手填的和 domain 預設的），維護者要判斷什麼時候該覆寫——而沒有人知道該怎麼判斷。
統一由 domain 預設，需要調整就調 domain 表，一次調完全部。

**`topic_hooks[].affinity` 為什麼要拿掉：** 它被當成 heat 塞進 Match 公式，
等於**人先給一個分數，再讓引擎算一個分數**。留一個就好，留引擎算的。

新增一位 KOL 要填的數字：**約 60 個 → 約 15 個**。

### 第四刀：熱度三訊號 → 兩訊號

```
現在：0.45·log(量體) + 0.35·成長率 + 0.20·互動率
提案：0.60·log(量體) + 0.40·成長率
```

互動率的問題不是它沒用，是**多數 Apify hashtag actor 根本不回傳這個欄位**。
現在唯一穩定有這個數字的是我手寫的範例資料——等於在拿假資料算分。
真的接上 Apify 之後，這一項會退化成常數 50，對排序毫無貢獻。

---

### 第五刀（最重要）：把「預測漏斗」換成「設定目標」

現況：從一個 `assumed: true` 的基準值，乘上 `lift = 0.7 + 0.6·(Match/100)`，
再乘上 `heatMultiplier = 0.85 + 0.3·(熱度/100)`，往下推五層，得到五個小數點以下的數字。

**那兩個乘數是我編的。** 沒有任何資料支持 Match 90 分會比 50 分多帶 30% 觸及。
五個看起來很精確的數字，全部建立在兩個沒有來源的係數上——這比不預測還糟，
因為它會讓人以為系統知道一些它其實不知道的事。

**提案：**

| | 現行 | 提案 |
|---|------|------|
| 預評 | 5 層漏斗預測 + 2 個乘數 | Match 分數 + 等級 + 四維判準 + **企劃者自己填 2 個目標**（目標觀看、目標外連點擊）+ 一句決策 |
| 後評 | 11 個指標欄位 | **3 個數字**（觀看、互動、外連點擊）+ 四維實測 |
| 對照 | 5 列 + 3 種偏差帶 + 5 種歸因 | **3 列** + 一句歸因 |

**人填的目標比假公式算的預測有用**：它逼企劃者說出「這支我期待什麼」，
而且事後對照時，落差是**對照一個人做過的判斷**，不是對照一個係數。
等累積夠實績，再回來討論要不要恢復自動預測——那時才有東西可以校準。

歸因規則同時簡化成兩句話：

- 觸及達標、點擊不足 → **素材問題**（CTA / 結尾）
- 觸及不足 → **選題或發布時機問題**

---

### 第六刀：刪掉校準迴圈

`calibration()`、Pearson 相關係數、每位 KOL 的建議基準值——
**這套機制要 10 筆完成後評估才會啟動，目前有 0 筆。**
它現在唯一的作用是在畫面上顯示「樣本 2 / 10」。

隨第五刀一起刪除。等真的累積到 10 筆、且有人真的想調參數時再寫，
那時候會比現在更清楚要校準什麼。
