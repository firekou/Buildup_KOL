## §0 這份規格的紀律

三條，違反任何一條這份規格就沒有價值：

1. **只有 `99-verification.md` 標記 ✅ 的文獻可以進入 Zone A。** 未驗證的一律進 Zone B，且預設關閉。
2. **不新增任何沒有出處的數字。** 現行 `WEIGHTS = 0.35/0.3/0.2/0.15` 是編的；**我們不會用另一組編的數字取代它**。
3. **每一個會影響決策的數字，畫面上都必須能看到它的意義、影響度與依據**（使用者指示 5）。看不到依據的數字，就是下一個 `0.35`。

### 兩個貫穿全案的方向判斷（使用者裁示）

- **Gemini 的批判為主軸。** 特別是「線性補償模型是錯的」這一刀。
- **心理量表派為評分主體。** 結構中心性派與擴散實證派**不進評分**，只作為約束與警示——因為它們需要歷史成效資料，而我們沒有。

這兩件事互相支撐：Gemini 最硬的批判（契合度是門檻不是權重）正是心理量表派的立場（Mandler 1982；Meyers-Levy & Tybout 1989）。

## §1 三區架構

使用者指示 1／2／3 對應三個**物理上分開**的區，不是三個標籤：

| 區 | 名稱 | 內容 | 預設 | 能否影響決策 |
|---|---|---|---|---|
| **A** | 已驗證核心 | 只用 ✅ 文獻 | 開啟，不可關 | ✅ 是 |
| **B** | 實驗區 | 未驗證／有爭議／需資料才成立 | **關閉** | ❌ 否（只顯示，標「實驗」） |
| **C** | 紅線與警示 | 一致認為不能做的 | 開啟，不可關 | ✅ 否決或警告 |

**強制隔離規則：** Zone B 的任何輸出**不得**進入 Zone A 的分數或 Zone C 的判定。程式上以獨立模組 + 獨立回傳欄位（`experimental`）實現，API 回應中 Zone B 的內容一律包在 `experimental: { ... }` 之下。

## §2 Zone A · 新的評分模型

### 2.1 核心改動：Gate 先行，熱度不再能買契合

**現況（要廢除）：**
```js
score = 0.35·personaFit + 0.30·pillarFit + 0.20·topicHeat + 0.15·regionFit
```
Gemini 的判詞：這是線性補償模型——「登山嚮導談專櫃粉底液」只要粉底液正在炎上，加權後仍可及格。

**新模型：**

```
第一階段  GATES（布林，不可補償，任一不過即停）
  ├─ G1  紅線命中（severity=block）              → VETO
  ├─ G2  具身違規（AI 不可能親身在場的主張）        → VETO
  ├─ G3  personaFit < FLOOR                     → VETO
  ├─ G4  無內容支柱可歸屬                         → HOLD（待人工綁定）
  └─ G5  資料完整性（軸缺 why／缺憑證型態）          → HOLD

第二階段  篩選分（只在全部 gate 通過後才計算）
  screeningScore = mean(fit, pillar, homophily, credibilityMode)   ← 等權
  ※ topicHeat 不在其中

第三階段  時機（並列顯示，永遠不進總分）
  timing = { heat, heatConfidence, timingCaveat }
```

### 2.2 為什麼是等權，而不是另一組權重

**這是本規格最重要的一個決定。**

我們沒有任何真實成效資料。任何非等權的權重都只能靠拍腦袋，那就是把 `0.35` 換成 `0.4` 而已。等權至少是一個**可辯護的無資訊先驗**——它宣告的是「我們不知道哪一維更重要」，這是真的。

熵權法（中文學術圈主流）在此**不適用**：GPT 指出它在小樣本與指標高度相關時會失準，而我們兩者都會踩到。
→ 權重校準列入 Zone B，**條件是累積 ≥30 筆有 `measuredAt` 的成效記錄**（見 §11 P3）。

畫面上每一個等權都要標註：
> ⚖️ 等權是刻意的先驗，不是校準值。累積 30 筆成效資料後才會重新計算。

### 2.3 `FLOOR`（G3 硬底線）怎麼定

Mandler 1982（✅ E1）確立「極度不契合無法被化解 → 直接負評」，但**原文沒有給任何 0–100 尺度上的切點**。Gemini 建議的 30 分同樣是憑空的。

**處理方式：** `FLOOR = 30`，但**明確標記為待校準的先驗**，且：
- 設定值放在 `kols/scoring-config.json`，不寫死在程式裡
- 卡在 `FLOOR ± 10` 的組合一律進 **`borderline` 佇列**並保留，作為未來校準底線的唯一資料來源
- UI 標註：「這條線目前是先驗。文獻確立『有一條線』，但沒說在哪裡。」

### 2.4 四個 Zone A 維度

| 鍵 | 名稱 | 量什麼 | ✅ 依據 |
|---|---|---|---|
| `fit` | 人設契合 | KOL 四軸能力 vs 話題四軸需求（需求加權達成率） | Ohanian 1990；Weng et al. 2010（分話題影響力） |
| `pillar` | 支柱契合 | 話題是否落在已宣告的內容支柱內 | Kamins & Gupta 1994；Speed & Thompson 2000；Zuckerman 1999 |
| `homophily` | 相似性 | KOL 與目標受眾在身分、處境、語言上的接近程度 | **Lou & Yuan 2019** — 四個信任前因之一，**我們現在完全沒有這一維** |
| `credibilityMode` | 可信度型態相符 | 這個主張屬於「具身經驗型」還是「資料庫型」，與該 KOL 的型態是否相符 | Sundar 2008 MAIN；Lee & Eastin 2021 PASMI |

**`homophily` 與 `credibilityMode` 是新增的**，而且是本次研究收穫最大的兩塊。

### 2.5 `pillarFit` 的三項修正（Zuckerman 1999）

現況實測（`92` 附錄）：`#离职` → 65.3、`#边界感` → 93.3，全部 `needsBinding: false`，**而 65.3 已跨過 B 級「可做」**。根因是 `max(candidates)` ＋ `keywordHit` 的 `0.7` 地板。

| # | 修正 | 理由 |
|---|---|---|
| M1 | **刪除過度泛用的 `pillar_keywords`**：`人生／职场／内耗／边界／决定／风险` 等 | 這些詞在任何帳號上都會命中，等於沒有邊界 |
| M2 | **`keywordHit` 地板 0.7 → 移除**，改為 `cov` 正常計算 + 命中加成上限 | 地板讓「關鍵字表愈寬愈有利」，方向與 Zuckerman 相反 |
| M3 | **支柱數量懲罰**：支柱 > 3 時，`pillar` 分數乘以 `3/n` | Zuckerman：身分歸類不清會被市場折價。目前 `max(candidates)` 是**獎勵**多支柱 |

M3 的 `3` 同樣是先驗，但它有方向依據（懲罰而非獎勵），且會標註。

### 2.6 `topicHeat` 從總分移出

依 Gemini Q3 的判詞——現行熱度「在衡量熱度與趨勢上是完全無效的」。它衡量的是「特定種子詞極小樣本下該詞彙的靜態共現密度」。

**新做法：**
- 熱度仍計算、仍顯示，但**不進總分**
- 新增 `heatConfidence`：`none` / `low` / `medium`，由**是否有時間序列**決定
  - 沒有 `topicSnapshots` 歷史 → `none`，UI 顯示「**無法判定升溫**」而非一個數字
  - 有 ≥7 天快照 → `low`（可算 z-score）
  - 有 ≥14 天且跨平台一致 → `medium`
- **永遠不會有 `high`**——除非改用平台官方 API

**UI 措辭強制規定（禁止出現的字）：** 「正在紅」「新趨勢」「爆紅」「跨圈潛力」。
在 `heatConfidence = none` 時，欄位標籤必須是 **「樣本共現密度」**，不是「熱度」。

### 2.7 熱度分 domain（Romero et al. 2011 ✅）

`classifyDomain()` 已存在，但跑在 `scoreHeat()` 之後。**調換順序**，改為同 domain 內 normalize。
理由：政治性題材是複雜傳染（需重複曝光），梗與慣用語不是；跨 domain 比較的不是同一個東西。

## §3 維度備註規格（使用者指示 5）

**每一個維度、每一個 gate、每一個分數，都必須攜帶一份 `note` 物件並在 UI 上可展開。**

### 3.1 Schema

```jsonc
{
  "key": "homophily",
  "label": "相似性",
  "meaning":  "白話：觀眾覺得「這個人跟我是同一種人」的程度。",
  "impact":   "high",              // high | medium | low
  "impactWhy":"這是四個「信任前因」之一。相似性低的時候，就算專業度很高，觀眾也只會覺得「他很厲害」而不會覺得「我該聽他的」。",
  "function": "決定這個 KOL 說的話會不會被當成「自己人的建議」，而不是「專家的評論」。",
  "evidence": [
    {
      "claim": "資訊價值、可信賴度、吸引力、與追隨者的相似性，四者正向影響追隨者的信任。",
      "source": "Lou & Yuan (2019), Journal of Interactive Advertising, 19(1), 58–73",
      "url": "https://doi.org/10.1080/15252019.2018.1533501",
      "status": "verified"
    }
  ],
  "failureMode": "選太高：人設會變得沒有專業距離，講什麼都像朋友閒聊，權威感消失。選太低：觀眾會佩服但不會行動。",
  "calibration": "prior"           // prior | verified | calibrated
}
```

### 3.2 `impact` 的定義（必須寫死，不能各憑感覺）

| 值 | 意義 | 判準 |
|---|---|---|
| `high` | 這一維單獨就能否決或翻盤 | 它是 gate，或它在等權模型中佔 ≥25% |
| `medium` | 會改變排序，不會改變 go/no-go | 進入分數但不是 gate |
| `low` | 只作參考，不進分數 | Zone B，或純顯示欄位 |

### 3.3 `calibration` 的三態（這是誠實度的核心）

| 值 | 意義 | UI 呈現 |
|---|---|---|
| `verified` | 這個做法有 ✅ 文獻直接支持 | 綠色，附文獻連結 |
| `prior` | 方向有依據，但**具體數字是我們定的** | **黃色，附「這個數字目前是先驗」** |
| `calibrated` | 已用 ≥30 筆真實成效資料校準過 | 藍色，附樣本數與日期 |

**目前全系統沒有任何一項是 `calibrated`。** 這件事要在首頁顯示，不能藏。

## §4 Zone B · 實驗區（預設關閉）

放進這一區的判準：**方向可能對，但依據不足以影響真實決策。**

| # | 項目 | 為什麼在 B 而不在 A | 出 B 的條件 |
|---|---|---|---|
| B1 | **倒 U 甜蜜點加成**（中度不契合區放大熱度乘數） | Mandler ✅ 確立倒 U 存在，但**沒有任何尺度上的區間**。Gemini 的「50–70」是憑空的 | 累積 ≥30 筆含 `borderline` 區間的成效資料，實際看到倒 U |
| B2 | **熵權法權重校準** | GPT：小樣本 + 指標高度相關時失準，兩者我們都會踩 | ≥30 筆成效 **且** 指標相關係數 < 0.7 |
| B3 | **TOPSIS 綜合排序** | 排序反轉問題：新增一個極端候選會改變原本兩者的相對名次 | 需先證明我們的候選集穩定 |
| B4 | **z-score 突發偵測** | 需要 ≥7 天 `topicSnapshots`，目前是 0 天 | 快照累積滿 7 天自動啟用（唯一會自動出 B 的） |
| B5 | **跨平台一致性加權** | `platformsSeen` 目前根本沒被讀取（bug，見 §11 P1） | bug 修好且累積足夠樣本 |
| B6 | **PSI / 關係存量指標** | 文獻上的中介變項，但零數據下無法測量 | 需真實帳號的 `follows` / 回訪資料 |

**UI 規則：** Zone B 的每一項都要有開關、要標「實驗」、要寫出**出 B 的條件**。使用者打開它時要跳一次確認：「這一項的依據不足以支撐真實決策，你確定要讓它影響排序嗎？」

## §5 Zone C · 紅線與警示（rule-based，轉為 skill）

使用者指示 3。分兩級：**`block`（一致認為不能做）** 與 **`warn`（有爭議或有代價）**。

### 5.1 `block` 級（全域，套用到所有 KOL）

| ID | 規則 | 依據 | 為什麼是 block |
|---|---|---|---|
| `R-EMBODIMENT` | 禁止任何要求 AI KOL 主張「我親身在場／親身經歷／我的身體感受」且不可查證的題目 | Sundar 2008 MAIN ✅；Lee & Eastin 2021 ✅ | 機器捷思對具身主張是**直接的否定證據**。被戳破一次，該人設的專業性不可逆 |
| `R-CREDENTIAL` | 禁止宣稱 AI 在結構上不可能取得的憑證（執照、認證、實地資歷） | 同上 | `rachel-ong` 的 `credibility: 95` 依據是「IFMGA 認證嚮導」——現行 `validateAxes()` 只檢查長度，抓不到 |
| `R-NO-WHY` | 沒有 `why`（或 < 10 字）的軸分數不得進入計算 | `docs/09` §0 原則二 | 已實作，升格為全域紅線 |
| `R-FAKE-CERTAINTY` | 禁止「絕對安全／零風險／保證成功／百分百」 | 既有 KOL 紅線，保留 | — |
| `R-STAGED-DANGER` | 禁止為互動率擺拍危險動作或誇大難度 | 既有，保留 | — |

### 5.2 `warn` 級（顯示但不阻擋）

| ID | 規則 | 依據 | 為什麼只是 warn |
|---|---|---|---|
| `W-ENGAGEMENT-BAIT` | 刻意留破綻／說錯話換留言 | Friestad & Wright 1994 ✅ 說服知識模型 | **模型間不一致**：Gemini 推薦，GPT 與 Claude 反對。受眾看穿意圖時，傷害的是對整個帳號的評價，不只這一則 |
| `W-OUTGROUP` | 以外團體敵意換互動 | Rathje et al. 2021 ✅；Brady et al. 2017 ✅ | 有效是真的（約兩倍），但 Brady 的邊界條件是**傳染受群體邊界限制**——買到的是同溫層深度，不是跨圈觸達 |
| `W-BLURRED-PILLAR` | 支柱數 > 3，或單一泛用關鍵字命中 | Zuckerman 1999 ✅ | 是折價不是否決 |
| `W-NO-BASELINE` | 在 `heatConfidence = none` 時做時機相關決策 | Kleinberg 2002 ✅ | 提醒，不阻擋 |

### 5.3 轉為專案 skill

**位置：** `.claude/skills/kol-redline-check/`

```
kol-redline-check/
├── SKILL.md              # 觸發條件與使用說明
```

## §6 引導式 KOL 創建（使用者指示 4a／4b）

新增路由 `/create`，**8 個步驟、每步一頁**，左側表單、右側**專家知識庫側欄**。

### 6.1 步驟

| # | 步驟 | 決定什麼 | 這一步的紅線檢查 |
|---|---|---|---|
| 1 | **用途與分群** | 這個 KOL 要做什麼：導流／品牌／社群經營／測試 | — |
| 2 | **可信度型態**（★ 最重要） | **具身經驗型 vs 資料庫型** | 選具身型 → 立刻警告不可逆風險 |
| 3 | **專業領域與憑證** | 領域、可查證的知識來源 | `R-CREDENTIAL` |
| 4 | **內容支柱** | 2–3 根，含權重 | `W-BLURRED-PILLAR`（>3 即警告） |
| 5 | **四軸自評 + why** | 每軸分數與理由 | `R-NO-WHY`（強制，寫不出 why 就不能填分） |
| 6 | **相似性設定** | 目標受眾的身分、處境、語言 | — |
| 7 | **紅線設定** | 全域紅線 + 這位 KOL 專屬的 | — |
| 8 | **檢核與產出** | 完整度檢查 → 產出 `profile.json` + `topic_affinity.json` | 全部 |

**第 2 步為什麼最重要：** 這是本次研究的最大單一發現。它決定了這個 KOL 的**整個風險結構**，而且事後幾乎改不了。

### 6.2 專家知識庫側欄（指示 4b）

每一個選項旁邊都有，四個固定區塊：

```
┌─ 💡 這是什麼（大白話） ─────────────────┐
│ 用國高中生聽得懂的話講，不准出現術語。      │
│ 出現術語就要當場解釋。                    │
└──────────────────────────────────────┘
┌─ 📊 選錯會怎樣 ──────────────────────┐
│ 具體後果，不是「可能影響效果」這種空話。    │
└──────────────────────────────────────┘
┌─ 📚 依據 ───────────────────────────┐
│ 論文＋連結＋一句話結論。                 │
│ 沒有 ✅ 依據的選項，這一格要寫「這是我們  │
│ 的判斷，目前沒有文獻支持」。              │
└──────────────────────────────────────┘
┌─ ✅ 建議 ───────────────────────────┐
│ 給一個明確推薦，不要列選項讓人自己想。     │
└──────────────────────────────────────┘
```

### 6.3 第 2 步的側欄實際文案（範例，其餘比照）

> **💡 這是什麼**
> 你要決定這個 KOL 的可信度是**靠親身經歷**，還是**靠整理知識**。
> 「靠親身經歷」＝她說「我爬過那座山，當時風很大」。
> 「靠整理知識」＝她說「根據這三份路線報告，那座山的風險是這樣」。
> 兩種都可以做出很好的內容，但它們**壞掉的方式完全不同**。
>
> **📊 選錯會怎樣**
> 這是一個 **AI 生成的角色**。當觀眾發現這件事的時候：
> - 選了「靠整理知識」→ **專業度可能反而上升**。因為大家會覺得 AI 客觀、不會偏心、能讀完所有資料。
> - 選了「靠親身經歷」→ **專業度會直接崩掉**。「我爬過那座山」這句話，對一個 AI 來說是假的，而且是所有人都能一秒看穿的假。
>
> 而且第二種**救不回來**。一旦被戳破，之後這個帳號講什麼都會被打折。
>
> **📚 依據**
> Sundar (2008) 的 MAIN 模型指出，人會用「這是機器做的」當成判斷可信度的捷徑——這個捷徑對「客觀分析」是加分，對「我親身在場」是**直接的反證**。
> → [MAIN Model](https://www.researchgate.net/publication/323990996)
> Lee & Eastin (2021) 的真實性量表也顯示，「真誠」與「透明揭露」在具身人設上會互相打架。
> → [JRIM 15(4), 822–841](https://www.emerald.com/jrim/article-abstract/15/4/822/451011/Perceived-authenticity-of-social-media-influencers)
>
> **✅ 建議**
> **選「資料庫型」。** 除非你有把握這個帳號永遠不會被問「你真的去過嗎」。
> 如果你真的要做具身型（例如登山、旅遊），請把主張改寫成可查證的形式：不要說「我走過」，要說「這條路線的紀錄顯示」。

### 6.4 產出

第 8 步產生的檔案**直接寫進 `kols/<id>/`**，格式為 schema v3（§9），並自動跑一次完整紅線檢查。**任何 `block` 未解決 → 不允許存檔。**

## §7 引導式話題查詢與挖掘（指示 4c）

新增路由 `/explore`，三個模式：

### 7.1 引導式查詢

不是一個搜尋框。是三步：
1. **你想找什麼？** 「跟我的支柱有關的」／「最近在動的」／「還沒人做的」
2. **範圍** 地區 × 平台 × 時間窗
3. **結果** 每一列都附「這個數字是什麼／不是什麼」

**第 3 步的強制標註：**
> 這不是平台熱度。這是**在我們用種子詞抓到的樣本裡，有幾個不同帳號用了這個標籤**。
> 種子詞決定了你能看到什麼——你看到的是「跟種子詞一起出現的字」，不是「大家在講什麼」。

### 7.2 挖掘（結構洞導向）

Burt 1992 ✅：新帳號要找的是**連接互不相通群體的位置**，不是熱度最高的位置。熱度高常代表已被過度消費。

實作：計算每個 tag 的**跨 domain 共現度**——同時出現在兩個不相關 domain 的 tag 標為「橋接候選」。
⚠️ 這一項標 `prior`：Burt 的理論 ✅，但「用 tag 共現當結構洞代理」是我們的推論，**不是文獻做法**。

### 7.3 探索與評估

對任一 tag：時間序列（若有快照）、domain 分佈、作者集中度、與各 KOL 的初步 gate 結果。

## §8 Match → 自動產生 5–10 個內容企劃（指示 4d）

### 8.1 產生邏輯

輸入：一位 KOL（含支柱、四軸、紅線、可信度型態）
輸出：**5–10 個企劃選項**，每個包含：

```jsonc
{
  "id": "...",
  "pillar": "轉身時刻 Turning-Back Moments",     // 必須綁定既有支柱
  "topic": "...",
  "angle": "...",                                 // 切角
  "task": "attention",                            // attention | comment | share（三選一，強制）
  "taskWhy": "為什麼這一支打這個目標",
  "format": "...",
  "hook": "...",                                   // 前 3 秒
  "gates": { "passed": true, "checked": [...] },
  "screeningScore": 71.2,
  "notes": [ /* §3 的維度備註 */ ],
  "risks": [ /* warn 級命中 */ ]
}
```

### 8.2 三個硬性約束

| # | 約束 | 依據 |
|---|---|---|
| C1 | **每個企劃必須綁定一根既有支柱**，不得產生「無支柱」的企劃 | Zuckerman 1999 ✅ — 不在支柱內的內容會稀釋帳號身分 |
| C2 | **`task` 三選一，不得多選** | 關注要「不一致被化解」、對話要「不一致不被化解」——**機制互斥**（Mandler 1982 ✅；Rathje 2021 ✅） |
| C3 | **全部通過 Zone C `block` 檢查才輸出** | 使用者指示 3 |

### 8.3 配額（`prior`，會標註）

10 個選項的建議分佈：**關注 4 ／ 對話 2 ／ 擴散 3 ／ 身分 1**。
⚠️ 這組數字**沒有文獻依據**，是為了強制三種任務都被想過。UI 上標 `prior`，且可調。

### 8.4 一句必須顯示的話

> 這些是**篩選過的候選**，不是預測。文獻上（Bakshy et al. 2011 ✅）預測哪一則內容會爆本身就不可靠——這個工具的價值在於**排除明顯錯的組合**，以及**逼你把理由寫下來**。
