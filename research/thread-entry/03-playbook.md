# 03 · 四個問題的正面回答

前兩份是限制條件。這一份是在限制條件裡，實際能做的事。

## 問題 1：要用什麼素材？

### 先刪掉不能用的

`02` 已經把這幾類刪掉了，這裡只列結論：

| 素材 | 為什麼不能用 |
|---|---|
| 從網路上找到的現成迷因圖 | Meta 非原創內容降觸及；第三方浮水印是被點名的負面訊號 |
| 帶連結的回覆 | X 明文禁止「回覆主要由無評論連結構成」；Meta 把低品質落地頁列為不推薦 |
| 跟原串無關但很吸睛的東西 | X 明文禁止「以與原貼文主題無關的內容回覆來推廣」 |
| 「同意的按讚」「留言 +1」 | Meta engagement bait 定義 |
| 做成真實截圖樣子的假圖 | X 合成媒體政策；Meta 誤導性內容 |

### 剩下的四類，按「新帳號應該優先用」排序

**第一順位：原創資訊圖（自己做的一張圖）**

一張把原串在吵的事情整理清楚的圖：一個對照表、一組數字、一條時間線。

為什麼排第一：
- **原創** —— 完全避開 Meta 非原創內容規則。
- **沒有 AI 標籤問題** —— 用程式或版面工具做出來的圖表不帶 C2PA/IPTC 生成標記。
- **對新帳號的可信度是加分而不是扣分** —— 它證明你做了功課。一個沒有追蹤者的帳號要建立可信度，能拿出來的只有「我算過」。
- **和現有系統相容** —— 我們的 `framework` 敘事形狀本來就是「列點 → 判準 → 觀念」，那個列點段落天生就是一張圖。

**第二順位：純文字的「判準句」**

不需要圖。一段 2–4 行的話，做一件事：把原串上大家在爭的那個東西，換成一個可以自己驗算的判準。

為什麼排第二：**製作成本近乎零，而且它是唯一能在「事件發生後 30 分鐘內」出手的素材形式。** 圖要做，字不用。時效性題目上，快是唯一的優勢。

**第三順位：自己生成的迷因圖**

可以做，但要知道代價：
- 用 AI 生圖 → Meta 會掛「AI info」標籤（`02` §2.4）。
- 新帳號 ＋ AI 標籤 ＋ 迷因，三個訊號疊起來，讀者的預設判斷是「這是機器人」。
- 這正是使用者說的「非殭屍」帳號要避免的印象。

**所以建議：新帳號的前 30 天不要用 AI 生成的迷因圖。** 等帳號有了一批看得出是人在經營的內容之後再加。這不是合規問題，是可信度的順序問題。

**第四順位：我們自己的具體案例**

「我們自己跑過一次，結果是 X」。這是四類裡可信度最高的，但**只有在跟原串題目直接相關時才能用**，否則就變成 X 明文禁止的那條。

### 一句話總結問題 1

> **新帳號能拿出來換注意力的，不是好看，是「我算過而且我可以告訴你怎麼算」。**
> 迷因是老帳號的武器，因為迷因靠的是既有的信任。新帳號沒有信任，只能靠可驗算的東西。

## 問題 2：整體要怎麼規劃？

### 2.1 平台順序：先 Threads，X 次之

理由是機制上的，見 `01`：
- Threads 的產品負責人親口說「回覆的總價值約等於貼文的總價值」，回覆是設計中心。
- X 的公開排序程式碼講的是首頁時間軸，回覆排序沒有公開；X 對回覆位置唯一的官方陳述是「訂閱可以買到輕微偏好」。

所以：**Threads 是主場，X 是需要花錢才有起跑線的客場。** 兩個都做，但資源分配不對等。

IG 不在這個玩法裡——IG 的留言區不是公共討論場，這一點使用者的直覺（「主要是 Threads 或 X」）本來就是對的。

### 2.2 帳號規劃：一個帳號，一個題目領域

兩個理由，都是機制性的：

1. **X 的 `SimClusters`**（`01` §1.1）要先把你歸進一個社群，才有辦法把你推給陌生人。什麼都碰的帳號歸不進任何一群。
2. **X 明文禁止 overlapping accounts**（`02` §1.3）。所以「開幾個帳號分別試不同題目」這個念頭，只要它們題材相似或互相互動，就是違規。

**明確不做：** 多帳號互推、買互動、找人代刷。X 寫得很清楚——「coordinating with or compensating others to engage in artificial engagement… **even if the people involved use only one account**」。這也是本 repo 的既有立場。

### 2.3 付費：X Premium 是唯一合規可買的位置

- X 自己把 reply prioritization 當功能賣，分 Basic / Premium / Premium+ 三級（`01` §2）。
- 這不是操縱，是平台自己的商品。
- 但 X 自己的用詞是「slight preference」而且「currently testing the levels」——**不要當成決定性變因**。

**建議：先訂最低階測 30 天。** 它是整個計畫裡最乾淨的單一變因——同樣的內容、同樣的節奏，只差有沒有訂閱。這正好是我們 Growth OS 的單因子實驗設計能吃的形狀。

### 2.4 節奏：時間分配要反過來

Mosseri 的建議是「reply much more than you post」。所以規劃不是「每天發幾則」，是：

| 動作 | 每日 | 依據 |
|---|---|---|
| 自有貼文 | 1 則 | 個人頁需要有東西給點進來的人看 |
| 進別人的串回覆 | 個位數，且集中在同一個題目領域 | Mosseri 的建議方向；同時遠離 X 的 bulk / aggressive 判定 |
| Threads tag | 每則貼文 1 個（上限就是 1） | Meta 自陳有 tag 的貼文 views 較高 |

**關於數量的誠實說明：** Threads API 的技術上限是 1000 回覆／24 小時（`01` §5）。這個數字和安全操作量之間差了兩到三個數量級。
**兩個平台都沒有公布「多少算 bulk」。** 上表的「個位數」是我們自己的保守設定，不是平台規則，也沒有任何官方數據支持它是最佳值。它的作用是先確保不會踩線，之後靠實測往上調。這一點列在 `99-unverified.md`。

### 2.5 第 0 步：先把個人頁做完，再開始回覆

這是最容易被跳過、但代價最大的一步。理由有兩個，一個是轉換，一個是合規：

- **轉換**：回覆是曝光，個人頁才是轉換。回覆做得再好，個人頁講不清楚你是誰，流量就在那裡蒸發。
- **合規**：Meta 明文說「have something in your profile (like your **profile photo or bio**) that goes against our Recommendation Guidelines」會導致**整個帳號**在一段時間內不被推薦（`02` §2.1）。個人頁不只是門面，它是帳號能不能被推薦的前置條件。

個人頁要在 3 秒內回答三件事：你是誰、你會講什麼題目、點這個連結會得到什麼。連結放這裡——**不是放回覆裡**。

## 問題 3：流動的路徑是什麼？

### 3.1 路徑本體

```
  熱門討論串（別人的流量）
        │
   ①    │  你的回覆要被排到看得見的位置
        ▼
  讀者滑到你的回覆
        │
   ②    │  這句話要有「可以帶走的東西」
        ▼
  讀者點你的頭像
        │
   ③    │  個人頁要在 3 秒內說清楚你是誰
        ▼
  追蹤　or　點 bio 的連結
        │
   ④    │
        ▼
  落地頁 → 產品
```

### 3.2 每一段的關卡、誰控制、能不能量到

| 段 | 關卡是什麼 | 誰控制 | 能量到嗎 |
|---|---|---|---|
| ① 回覆排序 | X：訂閱層級 ＋ 相關性、可信度、安全性（X 自陳）<br>Threads：對話品質（Meta 未公開細節） | **平台**（可用訂閱部分影響） | ❌ 兩個平台都不提供「我的回覆排第幾」 |
| ② 回覆本身 | 有沒有給出可帶走的東西 | **我們，100%** | ✅ Threads API 有單則的 views / likes / replies |
| ③ 個人頁 | 3 秒內講清楚你是誰 | **我們，100%** | ⚠️ Threads API 有帳號層級 views，但無法歸因到某一則回覆 |
| ④ 連結 | 落地頁品質 | **我們，100%** | ✅ 帳號層級 `clicks` ＋ 我們自己的 tracking link |

### 3.3 這張圖告訴我們三件事

**第一，我們能控制的只有 ②③④，而大部分人只想 ①。**
①（排到前面）是平台決定的，我們唯一的槓桿是 X 的訂閱，而且 X 自己說幅度輕微。把力氣花在①上，回報最低。②③是完全免費、完全由我們決定、而且目前完全沒有做的部分。

**第二，連結不能放在回覆裡——這是明文規定推導出來的，不是迷信。**
X 禁止「回覆主要由無評論連結構成」，並把「從對話中把流量導到網站／產品」直接定義為 commercially-motivated spam（`02` §1）。
所以正確結構是：**回覆裡零連結，連結只在個人頁。** 這同時是合規要求，也讓②→③這一段變成必經之路——讀者想知道更多，只能點頭像。

**第三，②→③ 這一段量不到，這是壞消息，要先說。**
Threads API 不提供「這則回覆帶來多少 profile click」（`01` §5）。X 的 API 在現行方案下也沒有這個粒度。
所以整條路徑最關鍵的一段轉換率，我們**看不到**。能做的只有時間相關性推估：在只發了這一則回覆的時段裡，帳號層級 views / follows 有沒有跳。

對照本 repo 既有的歸因階梯：**這只能記成 `modeled`，永遠不能記成 `direct`。** 系統要在 UI 上把這件事說清楚，不能讓操作者以為那個數字是實測的。

## 問題 4：這會如何影響素材的製作與發布方式？

前面三個問題的答案，反推回來對 Growth OS 產生六個具體改動。細節見 [`90-growth-os-changes.md`](90-growth-os-changes.md)，這裡先講「為什麼」。

**1. 素材多一種形狀：`reply`（回覆型）**
現在系統產出的是「一則自有貼文」——有開場句、有列點、有收尾。回覆是另一種東西：更短、必須扣住原串的題目、不能有連結、不能有 CTA。這不是把貼文剪短，是不同的規格。

**2. 每一則回覆素材必須綁定它要回的那則貼文**
因為 X 的紅線是「與原貼文主題無關」。要能檢查相關性，就必須知道原貼文是什麼。系統要存 `parentPostUrl` ＋ 原貼文摘要，否則事後既無法檢查也無法歸因。

**3. 多一道相關性檢查（gate）**
「這則回覆跟原串是同一個題目嗎？」——這正是 X 唯一那條可判定的紅線。
按本 repo 既有原則：**關鍵字比對只能當第一層，永遠不是判決**。判不清楚就往 `needs_human` 走，不能自動放行。

**4. 多一道 engagement bait 檢查**
偵測「同意的按讚」「留言告訴我」「+1」這類句型。這是 Meta 有明確定義的降觸及訊號，而且很容易被模型自己寫進收尾。

**5. 圖片素材要記錄 provenance，並在 UI 上警告**
如果走 AI 生圖，資產要記下它是 AI 生成的，並在發布前明白告訴操作者：**Meta 會自動掛 AI info 標籤**。
這不是擋下來，是讓操作者知道代價後自己決定。目前的生圖 adapter 回 `not_configured`，所以這一條是「等接上生圖時要一起做」，不是現在就缺。

**6. 追蹤連結的位置從「每則素材」變成「每個帳號」**
因為連結不進回覆、只進個人頁。這改變了歸因粒度：
- 現在：一則貼文一個 tracking link → 可以算出某一則的貢獻。
- 之後：一個帳號一個 bio link → 只能算出某一段期間的貢獻。
**這是歸因精度的實質下降，而且是政策逼出來的，不是設計選擇。** 系統要如實呈現這個限制，不能用一個看起來很精準的數字蓋過去。

## 執行順序（如果明天就要開始）

1. **今天**：把個人頁寫完——你是誰、講什麼題目、連結。這一步不需要任何系統支援，而且是後面所有步驟的前提。
2. **第 1 週**：只做 Threads，只用「純文字判準句」，每天 1 則自有貼文 ＋ 個位數回覆，每則貼文帶 1 個 tag。目的不是成長，是確認帳號沒有被降觸及。
3. **第 2 週**：加入原創資訊圖。同時開始記錄每一則回覆的 `parentPostUrl` 和發出時間——之後所有歸因都依賴這份紀錄。
4. **第 3 週起**：如果 Threads 有反應，再開 X 並訂閱 Basic，把「有無訂閱」當成單因子實驗。
5. **一個月後**：才考慮迷因圖。
