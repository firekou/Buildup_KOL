# 99 · 查不到、或只有二手來源的部分

**這一份的內容不可以拿來當決策依據。** 列出來是為了讓後續的人知道哪裡是空的，不要以為正文已經涵蓋。

## 1. X 現行的回覆排序權重：未知

網路上大量流傳一張 X 排序權重表（例如 reply 27x、retweet 20x、profile click 12x）。**本研究不採用**，理由有三：

1. 我沒有逐行核對 `the-algorithm` 原始碼中的對應檔案，只看到二手部落格轉述，彼此數字還不一致（有的寫 reply 13.5，有的寫 27）。
2. 那份程式碼是 **2023 年 3 月的快照**，X 之後已公開表示排序模型更換過。
3. 更關鍵的是**範圍錯了**：開源的是首頁時間軸（Home Timeline）排序，不是討論串內的回覆排序。就算權重數字正確，也不是在回答「我的回覆會排第幾」。

**要補這個洞的唯一方法是實測**，不是找更好的文章。

## 2. X Premium 的 reply prioritization 實際幅度：未知

X 自己的說法是「slight preference」而且「We're currently testing the levels」（`01` §2）。X 沒有公布幅度，也沒有公布之後是否調整過。存檔頁最新為 2025-03。

**這是可以用實驗回答的**——同樣的內容、同樣的節奏，只差有沒有訂閱。這正是我們單因子實驗設計能吃的形狀。

## 3. Threads 的回覆會不會單獨出現在 For You feed：未知

Mosseri 說回覆的總價值約等於貼文的總價值，也說回覆「helps with discovery」，但**沒有**說回覆會單獨出現在別人的 For You。Meta 也沒有公開文件說明。

這一條很重要，因為它決定了「回覆」到底是借別人的版面，還是自己也能被推。**目前無法確認，正文沒有假設它成立。**

## 4. Meta 非原創內容政策是否適用 Threads：未知

2025-07-14 的公告寫的是 Facebook（`02` §2.3）。Meta 沒說它同時適用 Threads。同集團的推薦準則已把「low-quality publishing」列為不推薦，方向一致，但**範圍未確認**。

正文的處理方式是保守假設它適用——因為假設它不適用而搬圖，代價是整個帳號降觸及。

## 5. 「多少回覆算 bulk」：兩個平台都沒有公布

X 禁止「bulk, aggressive, high-volume unsolicited replies」，但沒有給數字。Threads API 的 1000 則／24 小時是**技術額度**，明顯不是安全操作量。

`03` §2.4 的「個位數」是**我們自己訂的保守起點**，沒有任何官方數據支持它是最佳值。它的功能是先確保不踩線，之後靠實測往上調。

## 6. 新帳號是否有信任度爬升期（trust ramp）：未知

「新帳號前 N 天會被限流」是社群操作圈的普遍說法，但**兩個平台都沒有任何官方文件提到這件事**。我沒有找到一手來源。

正文因此沒有依賴這個假設。`03` 建議新帳號前期保守，理由是別的——處分階梯對新帳號特別致命（`02` §1.4），以及新帳號沒有可信度存量。

## 7. 取得路徑的風險：X 政策原文取自存檔

`help.x.com` 對 WebFetch、curl（含瀏覽器 UA）與 Exa 一律回 403 / SOURCE_NOT_AVAILABLE。`02` 引用的 X 政策原文來自 archive.ph 存檔頁（2025-01）、OpenTermsArchive 版本紀錄，以及 X 提交給美國加州與紐約州檢察長的法遵報告。

**內容是 X 自己寫的，但取得路徑是第三方存檔。** 最新存檔為 2025-01，距今約 19 個月。正式決策前應該用瀏覽器人工開一次原始頁確認條文沒有變動。

## 8. IG 完全沒有研究

使用者說「主要是 Threads 或 X」，所以 IG 只在 `03` §2.1 用一句話帶過，**沒有查證**。如果之後要做 IG，這份研究不涵蓋。

## 9. 沒有任何成效數據

這份研究**沒有**回答「這樣做能帶來多少流量」。沒有基準值、沒有轉換率、沒有預期成長曲線。

任何看起來像這類數字的東西，如果出現在這份研究裡，都是錯的。第一批真實數字只能從 `03` 的執行順序跑完第 1–2 週之後才會有。
