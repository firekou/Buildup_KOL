> **Status（2026-07-10）**：本文件依使用者指定的**反證法**重做一次方案選擇——先把「行不通的」全部
> 判死,再從倖存者裡甄別。相較 `04`(先選 LiveTalking)是「正面論證」,本文件是「反面消去」,兩者
> **結論一致但路徑互補**,並補進兩個 `04` 尚未涵蓋的新條件:
>

> 2. **真實感標竿**:使用者以 `https://app.liangliang.biz/`(標題「AI Companions-Muse」,照片級真實感
>    數位人 App)為可接受的真實感標準。

## 1. 第一輪消去 — 整類判死(靠硬條件,證據見 `04` 與本輪三個查證)

| 判死對象 | 踩到哪條 | 判定依據 |
|---|---|---|
| 雲端 SaaS 虛擬人(HeyGen / D-ID / Synthesia / Tavus / Beyond Presence) | HC1(非本地)+ 使用者明言排除 + 大動作弱 | 使用者本輪明確排除 |
| 風格化虛擬形象(Open-LLM-VTuber / VTube Studio + Live2D / VRM) | HC3(不是真人) | 形象是 2D/3D 卡通 |
| 只動嘴的單張照片 talking-head(SadTalker 單圖、基礎 Wav2Lip 貼靜態圖) | HC4(身體不動) | 照片驅動,無肢體動作 |
| 批次型 diffusion talking-head 當「即時」用(Hallo2 / Sonic / FLOAT / JoyVASA 即時化) | HC5(非即時) | 生成一段影片,非即時串流 |
| 純 x86 CPU + 開源即時真人對嘴(Wav2Lip/MuseTalk CPU) | HC7(達不到 25fps) | 社群實測 CPU 掉到 32fps/OBS 崩潰、離線僅 ~0.5x 實時 |
| AMD GPU 跑 LiveTalking/Ditto | HC7(依賴 CUDA/TensorRT) | 綁 NVIDIA |
| **通用內建 TTS(Piper / EdgeTTS / Kokoro 等非克隆)** | **HC6(機械感,無特定真人溫度)** | 使用者親耳判定 + Kokoro 無克隆能力 |
| **聲音克隆但授權非商用(IndexTTS-2 / Fish-OpenAudio S1 / F5-TTS / XTTS-v2)** | **HC8(禁商用)** | 各權重 license 實查(見第 3 節) |

**第一輪淘汰掉的,正好是外行最容易一頭栽進去的**:雲端 SaaS(最好用但非本地)、動漫 VTuber(最好做
但不是真人)、單圖 talking-head(最炫的 demo 但不會動身體)、以及「聽起來最像真人卻不能商用」的
那批克隆模型。反證法的價值就在這——**先把這些死路標記清楚,避免把時間投在注定過不了關的方向。**

## 2. 倖存者(分三層,各層獨立甄別)

目標鏈可拆成三個可獨立抽換的層,每層各自做完消去後的倖存者如下:

```
[你打字] → (2A 聲音層) → (2B 形象+肢體層) → (2C 直播輸出層) → [平台觀眾]
```

### 2A 聲音層(HC2 + HC6 + HC8)
- **首選:VoxCPM**(OpenBMB/清華)— Apache-2.0 全商用、2026 中文自然度實測最高評價、**唯一官方支援 CPU**、
  一行 pip、3–10 秒克隆、支援串流。
- **次選:CosyVoice 2**(Alibaba)— Apache-2.0、原生 bi-streaming 首包 150ms、阿里生產級,適合**有 GPU
  的即時直播上線**。Qwen3-TTS(Apache-2.0、首包 97ms)為同陣營新鮮備援。
- **關鍵觀念**:溫暖/台味不是模型內建,是**從參考音複製**的。需準備一段乾淨、帶親切帶貨情緒的
  **台灣國語**參考音(zero-shot 15–30 秒;GPT-SoVITS 微調備 1–5 分鐘)。

### 2B 形象 + 肢體層(HC1 + HC3 + HC4 + HC5 + HC7 + HC8)
關鍵事實(來自 `04` 引用的 Evelyn 直播報告 + 本輪查證):**即時「原創」肢體動作生成尚不成熟,業界主流
是「真人實拍動作片庫 + 動作編排(action orchestration)觸發 + 語音驅動嘴型」**——這正好命中 HC4。
- **即時(有 NVIDIA GPU):LiveTalking**(8.4k★、Apache-2.0、2026-06 仍發版)— 唯一「本地+真人臉+即時
  串流」全鏈單一 repo,且**內建全身影片拼接 + 動作編排**,肢體動作靠實拍片庫觸發。
- **離線出片(無高階 GPU,退而求其次):** 授權乾淨且可商用者為 **EchoMimic V2(Apache-2.0、半身、真實感高,
  需 NVIDIA)**;純 CPU 唯一存活是 **SadTalker(Apache-2.0、有 `--cpu`)但畫質偏假、身體動作弱**(HC4 邊緣)。
- **無 NVIDIA GPU 的即時例外:bitHuman**(閉源商用 SDK,CPU/Apple Silicon 宣稱 25fps)——但**閉源+計費
  心跳連線+商業授權**,讓 HC1(本地)打折,列為 Apple Silicon 情境的唯一即時候選。

### 2C 直播輸出層(HC5)
無爭議:LiveTalking 原生 WebRTC/RTMP/虛擬攝影機;離線出片則 mp4 → OBS 媒體源/播放清單 → RTMP。
**建議一律走「虛擬攝影機 → OBS → 平台」**,最有彈性(可疊字幕、商品卡、場景切換)。

## 3. 聲音層第二輪消去的關鍵證據(授權)

「最溫暖」與「能商用」兩份名單幾乎不重疊,這是本輪最重要的發現:

| 模型 | 溫暖度 | 授權 | 判定 |
|---|---|---|---|
| IndexTTS-2 | ★ 最高(有人聽不出是 AI) | 權重 Bilibili 自訂**非商用** | ❌ 判死(除非另購授權) |
| Fish-Speech / OpenAudio S1 | ★ 極高 | 權重 CC-BY-NC-SA(非商用) | ❌ 判死 |
| F5-TTS | 高 | 權重 CC-BY-NC(非商用) | ❌ 判死 |
| XTTS-v2(Coqui) | 高 | CPML 非商用 + 公司已倒 | ❌ 判死(連買授權對象都沒了) |
| **VoxCPM** | 高(2026 中文實測最高評價) | **Apache-2.0** | ✅ **首選** |
| **CosyVoice 2** | 高 | **Apache-2.0** | ✅ **次選(串流最穩)** |
| GPT-SoVITS | 中(需調校) | MIT | ✅ 存活(有目標人聲、願微調時) |

## 4. 消去後的收斂結論(依硬體分三種情境)

**方案本身已無懸念,唯一決定走哪條的是硬體(HC7)。** 三種情境各自的存活組合:

| 硬體情境 | 聲音 | 形象+肢體 | 直播 | 即時? | 整體可行性 |
|---|---|---|---|---|---|
| **A. NVIDIA RTX 3060+（12GB↑）** | CosyVoice 2 克隆(或 VoxCPM) | **LiveTalking**（Wav2Lip256/MuseTalk + 動作編排,實拍片庫） | 虛擬攝影機→OBS→RTMP | ✅ 即時互動 | **~90%（最高）** |
| **B. 無高階 GPU / 純 CPU** | **VoxCPM**（CPU 可跑,較慢） | 實拍片庫 + EchoMimic V2（需借一次 GPU 出片）或 SadTalker（純 CPU、畫質妥協） | mp4→OBS 播放清單→RTMP | ❌ 照稿播放 | ~70–80%（畫質/即時性打折） |
| **C. Apple Silicon（M 系列）** | VoxCPM（MPS） | **bitHuman**（閉源,唯一即時真人）或離線出片 | 同上 | ⚠️ bitHuman 可即時但非純本地 | ~75%（本地/開源需讓步） |

**推薦主線 = 情境 A**:一張 RTX 3060(12GB)即把整體可行性推到 ~90%,且是唯一同時滿足 HC1–HC8 全部
八條的組合(bitHuman 破 HC1,SadTalker 弱 HC4,離線出片破「即時」)。

## 5. 唯一未知數 = 你的硬體(必須你回答)

反證法把問題收斂到極乾淨:**其餘變數都已定案,只剩「你要跑這套的機器是哪一種」尚未確定**,而它
決定落在情境 A/B/C 哪一格。需要你回答:

1. **GPU**:NVIDIA RTX 3060 以上 / NVIDIA 低階或筆電 GPU / Apple Silicon / 無獨顯純 CPU?
2. **直播形式**:先照稿播放就好 / 要即時互動 / 先照稿之後升級即時?

回答後即可鎖定唯一存活組合,把架構完全定死並開始落地。

## 6. 已經驗證/已落地的部分(不是紙上談兵)

- **聲音層鏈路已在無 GPU 的 CPU 環境跑通並可產音檔**:`companion/src/companion/voice/`(見 `05` 文件)。

  正式採 VoxCPM/CosyVoice)。
- **CPU 克隆速度實測(2026-07-10,本 sandbox 4 核 CPU 無 GPU)**:F5-TTS 生成一句約 10 秒中文語音,
  純 CPU 推理耗時 **329 秒(5 分 29 秒)= 約 32× 慢於實時**。這印證第 4 節判定:**純 CPU 跑克隆語音
  即使「能出檔」也遠不足以即時直播,連離線批次出片都很痛苦**;要做即時語音(HC5+HC6 同時成立),
  聲音層也需要 GPU(或改用官方 CPU 最佳化的 VoxCPM 並接受批次延遲)。這是「情境 B 純 CPU」被評為
  ~70–80% 而非更高的具體原因之一。
- **形象+肢體層**:方案與硬體門檻已查證定案(本文件),落地待第 5 節硬體確認後,由
  `livestream-tech-specialist` 依 `04` 第 6 節步驟實跑。
