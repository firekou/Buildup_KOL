# 社群影響力：評估指標與理論方法 — 研究總索引

> 「做不是問題，有理論支撐並轉化為系統化操作才是關鍵。」

本目錄回答三個問題，而不是「怎麼做 KOL」：

1. **KOL 的屬性要怎麼被確定？** 憑什麼說某個人設適合某個題？
2. **時事流量要怎麼被判定？** 什麼叫「這個話題正在熱」，而不是「這個字剛好出現很多次」？
3. **什麼樣的創意會產生共鳴、關注或對話？** 這件事有沒有可預測的規律？

---

## 一、研究方法（先講清楚，因為它決定了每份報告可以被信任到什麼程度）

問 LLM「有哪些論文」，它會產生看起來完全正確、實際不存在的引用——這是已知且高頻的失敗模式。
所以本研究的設計是**分兩層，兩層的信任等級不同**：

| 層 | 產出 | 取得方式 | 信任等級 |
|---|---|---|---|
| **底稿層** | `01-claude-literature.md` | Claude 用真實網路檢索，每一筆都附可點開的連結 | 引用可查證 |
| **線索層** | `02` ~ `05`（GPT / Gemini / 千問 / 豆包） | AI Token King MCP 呼叫各模型 | **引用一律視為未驗證**，價值在理論框架與視角差異，不在書目 |
| **驗證層** | `99-verification.md` | 對線索層的關鍵引用逐筆回查 | 標記 已驗證 / 查無此文 / 無法確認 |
| **收斂層** | `90-synthesis.md` | 內部 agent 團隊梳理三大體系 | 只採用通過驗證層的內容 |

換句話說：**四個外部模型是用來擴大提問的視野，不是用來當書目來源。**

## 三、五個模型被問的是同一組問題

為了讓五份報告可以橫向比較，所有模型收到的是**同一份題綱**（見 `01` 附錄）。差異只來自模型本身，不來自提問。

## 四、與本 repo 現有系統的關係

現有的選題 Dashboard（`dashboard/`、方法論在 `docs/09`）已經在做四維 Match 評分。
本研究的作用是回答一個很尖銳的問題：**那四個維度、那組權重，是有理論根據，還是我們自己編的？**
`01` 的每一節末尾都有「→ 對照現有系統」，明確標出三種狀態：

- **有支撐**：文獻支持現在的做法
- **無支撐**：現在的做法是工程上的方便，文獻上沒有依據
- **被推翻**：文獻明確指出現在的做法會錯
